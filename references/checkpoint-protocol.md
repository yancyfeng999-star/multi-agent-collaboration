# 对话与检查点协议

## 三层上下文

1. `archive/`：平台可见完整对话镜像，包含消息、工具调用/结果、错误、重试、修改和验证；默认脱敏，不可被摘要替代。
2. `checkpoints/CP-NNNN.md`：不可变压缩快照，链式引用前一检查点和真实 archive。
3. `CURRENT_CONTEXT.md`：短小的当前恢复入口，指向最新检查点、当前任务和必要资料。

## 创建顺序

1. 使用 `sync_conversation.py` 同步可见原文并记录平台、会话 ID、消息范围、脱敏状态和内容哈希。
2. 准备包含所有必填栏目的 checkpoint 正文。
3. 使用 `create_checkpoint.py` 校验 archive 引用并创建新 CP。
4. 脚本原子更新 `CURRENT_CONTEXT.md`，旧 CP 不覆盖。
5. 运行 `rebuild_index.py` 与 `validate_agents.py`。

## 触发条件

任务完成、问题域切换、关键决策、交接、会话关闭/迁移、平台原生压缩前，或总控阶段性收口时创建检查点。

## 必填内容

长期使命、当前总目标、当前任务与状态、已确认需求、关键决策及原因、已完成事项、修改文件、命令与真实结果、失败尝试、未解决事项、风险与假设、下一步、恢复时必读和按需原文。

## 硬规则

- 先原文后检查点；无法导出时明确记录缺口，不伪造原文。
- 摘要结论必须可回溯；不确定项标为假设或待验证。
- 计划不能写成完成；失败和未解决事项不能丢失。
- 源码、Git、测试或原文与 checkpoint 冲突时，以真实事实为准，创建更正 CP，不静默覆盖。
- archive/checkpoint 禁止包含凭据正文。
